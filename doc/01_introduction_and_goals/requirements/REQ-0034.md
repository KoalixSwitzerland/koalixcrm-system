# REQ-0034: Das System scannt wöchentlich das aktuelle Release-Image, berichtet und blockiert nie

## Lizenzseite
Open-Source-Backend (`/app/koalixcrm`, GitHub-Actions-Workflow)

## Quelle
Entscheidung des Product Owners 2026-10-25; ORG-BE-ADR-0015 §7 (wöchentlicher Lauf) und §8
(Workflow auf dem Standard-Branch).

## Why
Hinweise erscheinen nach dem Merge und nach dem Release, ohne dass sich Code ändert. Der wöchentliche
Lauf findet sie in Bibliotheken und Basis-Image, ohne ein ausgerolltes Release zu blockieren.

## Beschreibung
Ein zeitgesteuerter Workflow ruft den wiederverwendbaren Workflow des zentralen Repositories (REQ-0032)
auf und scannt einmal pro Woche das aktuelle Release-Image: `koalixcrm_django` und `koalixcrm_celery` in
der Version des jüngsten Releases. Der Lauf blockiert nichts. Er endet rot, solange der Bericht einen
Befund der blockierenden Klasse nach REQ-0029 enthält, damit GitHub benachrichtigt, und wird grün, sobald
das Image aktualisiert ist. Die Workflow-Datei liegt auf dem Standard-Branch `develop`.

## Acceptance Criteria

### AC-1: Zeitsteuerung
- [ ] Ein Workflow startet einmal je Woche per Zeitplan (`schedule`).
- [ ] Der Zeitplan fällt in denselben Wochenzyklus wie die Dependabot-Aktualisierungsvorschläge (REQ-0037).
- [ ] Die Workflow-Datei liegt auf dem Branch `develop`, dem Standard-Branch des Repositories.
- [ ] Der Workflow ist zusätzlich manuell auslösbar.
- [ ] Der Workflow ruft den wiederverwendbaren Workflow des zentralen Repositories mit dem Commit-SHA-Pin aus REQ-0032 auf.

### AC-2: Scan-Gegenstand
- [ ] Der Lauf scannt das Image `koalixcrm_django` in der Version des jüngsten Releases.
- [ ] Der Lauf scannt das Image `koalixcrm_celery` in der Version des jüngsten Releases.
- [ ] Der Lauf erfasst Befunde in Bibliotheken und in Betriebssystempaketen.

### AC-3: Bericht und Farbe
- [ ] Der Lauf schreibt den Bericht in die Zusammenfassung des Laufs.
- [ ] Der Lauf hängt den Bericht als Artefakt an.
- [ ] Der Lauf endet rot, wenn der Bericht mindestens einen HIGH- oder CRITICAL-Befund in einer Anwendungsbibliothek ohne gültige Ausnahme enthält.
- [ ] Der Lauf endet grün, wenn der Bericht keinen solchen Befund enthält.
- [ ] Ein Befund in einem Betriebssystempaket allein lässt den Lauf nicht rot enden.
- [ ] Der Lauf wertet Scanner- und Datenbankfehler als Fehlschlag.

### AC-4: Wirkung
- [ ] Der Lauf blockiert keinen Merge, kein Release, keinen Rebuild und kein Deployment.
- [ ] Der Lauf legt kein Issue an.

## Quality Attributes
- **Verfügbarkeit**: Ein neuer Hinweis gegen das Release-Image wird innerhalb von 7 Tagen im Lauf sichtbar.
- **Security**: Der Lauf fordert ausschließlich lesende Berechtigungen und die Berechtigung zum Lesen der Images an.

## Affected Components
- Backend: `.github/workflows/` (Wochen-Workflow auf `develop`)
- Frontend: keine
- Deployment: Lesezugriff auf die Image-Registry

## Not in Scope of this Requirement
- Das automatische Anlegen von Issues.
- Ein tägliches Scan-Intervall.
- Das Scannen von Test-Images im Wochenlauf.

## Dependencies
- REQ-0029, REQ-0030, REQ-0031, REQ-0032, REQ-0036, REQ-0037
- ORG-BE-ADR-0015 §7 und §8, ADR-0022
