# REQ-0032: Das System bezieht den Scan aus dem öffentlichen zentralen Repository `QuantalQ/quaq-vulnerability-scan`, fixiert per Commit-SHA

## Lizenzseite
Open-Source-Backend (`/app/koalixcrm`, Workflow-Aufrufe und Dependabot-Konfiguration). Das zentrale
Repository ist öffentlich und enthält keine produkt- oder kundenspezifischen Informationen.

## Quelle
Entscheidung des Product Owners 2026-10-25; ORG-BE-ADR-0015 §5; ADR-0022 (Bindung des Pins).

## Why
Ein öffentliches Open-Source-Repository kann Aktionen aus einem privaten Repository nicht verwenden.
Ein gemeinsamer Scan verhindert, dass jedes Produkt Schwelle, Konfiguration und Ausnahmeprüfung selbst
nachbaut und die Kopien auseinanderlaufen.

## Beschreibung
Das Repository `QuantalQ/quaq-vulnerability-scan` stellt den gemeinsamen Scan bereit: die Aktion
`trivy-image`, den wiederverwendbaren Workflow für den wöchentlichen Lauf, die gemeinsame
Trivy-Konfiguration `trivy.yaml`, das Skript für den lokalen Lauf und die Prüfung der Ausnahmeeinträge.
`koalixcrm` ruft diese Teile in seinen Workflows auf, fixiert sie per vollständigem Commit-SHA und lässt
Dependabot den Pin über das Ökosystem `github-actions` aktualisieren. Eine Änderung der gemeinsamen
Konfiguration erreicht `koalixcrm` damit als geprüfter Pull Request.

## Acceptance Criteria

### AC-1: Nutzung des zentralen Scans
- [ ] Jeder Workflow von `koalixcrm`, der Images auf Schwachstellen scannt, ruft die Aktion `QuantalQ/quaq-vulnerability-scan/...` auf.
- [ ] Der wöchentliche Workflow ruft den wiederverwendbaren Workflow des zentralen Repositories auf.
- [ ] Kein Workflow von `koalixcrm` enthält eine eigene Trivy-Aufrufkonfiguration neben dem zentralen Scan.
- [ ] Schwelle und Paketarten stammen ausschließlich aus der gemeinsamen `trivy.yaml`.

### AC-2: Fixierung
- [ ] Jeder Aufruf `uses: QuantalQ/quaq-vulnerability-scan/...@<sha>` fixiert das zentrale Repository mit einem vollständigen Commit-SHA (40 Zeichen).
- [ ] Alle Aufrufe in den Workflows von `koalixcrm` verwenden denselben Commit-SHA.
- [ ] Kein Aufruf verwendet einen Branch-Namen oder ein Tag.

### AC-3: Aktualisierung
- [ ] `.github/dependabot.yml` deklariert das Ökosystem `github-actions` für das Verzeichnis `/`.
- [ ] Dependabot schlägt Aktualisierungen des Pins als Pull Request vor.

### AC-4: Lizenzgrenze
- [ ] Das zentrale Repository ist öffentlich.
- [ ] Der gemeinsame Scan enthält keine Quantalq-internen URLs und keine kundenspezifischen Informationen.

## Quality Attributes
- **Wartbarkeit**: Ein Pin je Repository; nichts ist von Hand gleichzuhalten.
- **Security**: Eine fehlerhafte Änderung am zentralen Repository erreicht `koalixcrm` erst durch einen geprüften Pull Request.

## Affected Components
- Backend: `.github/workflows/`, `.github/dependabot.yml`
- Frontend: keine
- Deployment: keine

## Not in Scope of this Requirement
- Die Entwicklung des zentralen Repositories.
- Der Inhalt der gemeinsamen `trivy.yaml` über die Schwellen aus REQ-0029 hinaus.
