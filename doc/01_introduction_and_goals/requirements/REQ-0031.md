# REQ-0031: Das System führt Ausnahmen in genau einer Datei `.trivyignore.yaml`, jeder Eintrag mit Begründung und Ablaufdatum

## Lizenzseite
Open-Source-Backend (`/app/koalixcrm`, Datei im Repository) und gemeinsamer Scan (REQ-0032)

## Quelle
Entscheidung des Product Owners 2026-10-25; ORG-BE-ADR-0015 §4; ADR-0022 (Bindung der Ausnahmedatei).

## Why
Ein HIGH/CRITICAL-Befund ohne behobene Version blockiert den Merge, bis ein Hersteller-Fix erscheint.
Eine Ausnahme ohne Ablaufdatum bleibt versehentlich dauerhaft, und Trivy erzwingt weder Begründung noch
Ablaufdatum von sich aus.

## Beschreibung
Das Repository hat genau eine Ausnahmedatei `.trivyignore.yaml` im Wurzelverzeichnis im Trivy-eigenen
Format. Jeder Eintrag benennt die Schwachstelle und, soweit Trivy es unterstützt, Pfade oder Paket-URLs,
trägt eine nicht leere `statement` mit der Begründung oder dem Warten auf einen Fix und ein
Ablaufdatum `expired_at`. Ab dem Ablaufdatum gilt der Eintrag nicht mehr, und der Befund blockiert wieder.
Der gemeinsame Scan prüft die Datei vor dem Scan. Ausnahmen betreffen Anwendungsbibliotheken. Die Datei
wird wie Code im Pull Request geprüft.

## Acceptance Criteria

### AC-1: Eine Datei, eine Schwelle
- [ ] Das Repository enthält genau eine Ausnahmedatei `.trivyignore.yaml` im Wurzelverzeichnis oder keine.
- [ ] Jeder Scan des Repositories verwendet diese Datei.
- [ ] Das Repository kennt kein weiteres Ausnahmeformat und keine Bewertungsdatei mit eigenem Vokabular.
- [ ] Das Repository kennt keine feste Höchstdauer außer dem Ablaufdatum je Eintrag.

### AC-2: Eintragsregeln
- [ ] Jeder Eintrag enthält ein nicht leeres Feld `statement`.
- [ ] Jeder Eintrag enthält ein Feld `expired_at`.
- [ ] Ein Eintrag gilt nach dem Datum `expired_at` nicht mehr, und der Befund blockiert wieder.
- [ ] Ein Eintrag kann Pfade und Paket-URLs im Umfang angeben, den Trivy unterstützt.

### AC-3: Prüfung durch den gemeinsamen Scan
- [ ] Der gemeinsame Scan schlägt fehl, wenn ein Eintrag kein nicht leeres `statement` enthält.
- [ ] Der gemeinsame Scan schlägt fehl, wenn ein Eintrag kein `expired_at` enthält.
- [ ] Der gemeinsame Scan schlägt fehl, wenn die Datei kein gültiges YAML ist.
- [ ] Der gemeinsame Scan führt diese Prüfung vor dem Scan aus.
- [ ] Die Prüfung gilt gleich lokal und in CI.
- [ ] Eine fehlende Datei gilt als Datei ohne Einträge.

### AC-4: Review
- [ ] Die Datei liegt im Repository und unterliegt demselben Pull-Request-Review wie Code.
- [ ] Die Datei enthält keine Zugangsdaten und keine Quantalq-internen URLs.

## Quality Attributes
- **Auditierbarkeit**: Die Git-Historie der Datei belegt, wer wann welche Ausnahme eingebracht hat.

## Affected Components
- Backend: `.trivyignore.yaml` im Repository-Wurzelverzeichnis
- Frontend: keine
- Deployment: keine

## Not in Scope of this Requirement
- Ausnahmen für Betriebssystempakete.
- Die fachliche Richtigkeit der Begründung; das Review prüft sie.
- Automatische Verlängerung abgelaufener Einträge.
